# 交互细节优化清单

范围：`src/AvaloniaAssistant.UI` 的全部页面（首页、对话、侧栏、设置、技能、MCP）与几条关键运行时路径。
方法：逐文件读交互代码，配合 `--screenshot` 出的真实界面（`artifacts/ux-review-home.png`、`artifacts/ux-review-chat.png`）核对。
每条都标了代码位置和验收条件，可以直接拆成 issue，不用再回来问我"具体指哪里"。

> **状态（2026-10-24 13:45）**：P0-1 ~ P0-4 已修复，`dotnet build` 0 错误、101 个测试通过，
> 验证范围见文末「P0 修复记录」。下面保留原始分析，作为判断依据。

先说结论：这个项目的交互底子比多数自研客户端扎实——输入法回车保护、滚动跟随的主动交还、草稿跨页保留、权限切换进消息流、"已放行 N"角标，这些都是踩过坑之后补的，不是抄来的模板。所以下面挑的全是**还在漏的地方**，没有"推倒重做"的建议。

## 最值得先做的五件事

| 顺序 | 问题 | 为什么排前面 | 改动面 |
| --- | --- | --- | --- |
| 1 | 生成过程中按 Enter 没有任何反应 | 每次生成期间补一句话都会撞上，且是静默失败 | 输入框，1 个文件 |

## 评估口径

优先级不是按"看起来丑不丑"排的，按三件事排：

- **触发频率**：一天多次 > 一周几次 > 装完只碰一次。
- **卡住的代价**：静默失败（不知道发生了什么）> 不可逆（删了就没了）> 要多绕三步 > 轻微不适。
- **有没有替代路径**：没有替代的才算硬伤。

据此分档：

| 档位 | 判据 | 处理节奏 |
| --- | --- | --- |
| P0 | 高频，且静默失败 / 不可逆 / 无替代 | 下一个迭代必须修 |
| P1 | 高频但有绕法，或中频但代价高 | 排进两三个迭代 |
| P2 | 低频、纯观感，或一次性成本 | 顺手做，别专门开排期 |

# P0

## P0-1 生成中按 Enter 静默失败

影响：高频 · 静默 · 无替代

**现在**：`ComposerViewModel.CanSend()` 在 `IsBusy` 时返回 false；`ComposerView.OnInputKeyDown` 先 `e.Handled = true`，再判断 `CanExecute`（`Views/ComposerView.axaml.cs:130-139`）。同时发送键在生成期间被换成停止键，界面上"发送"这个动作整个消失了。

模型正在流式输出，用户想补一句"顺便把结果写成文件"，敲 Enter：不发送、不换行、光标原地不动。敲第三次之后，他会开始怀疑是不是卡了。

**目标**：把"现在不能发"变成一个能解释的状态，并给出出路。

**怎么改**：两条路，按成本选。

1. 轻：Enter 时若 `IsBusy`，不吞按键，而是在输入框下方已有的 `ActivityText` 通道里写一句"正在生成，完成后按 Enter 发送"，并把发送键做成半禁用态（可见、按下有回执）而不是直接消失。
2. 彻底：做排队。Enter 把内容存为 pending，本轮结束自动发出；输入框立刻清空，下方显示"将在本轮结束后发送"，并提供"取消排队"。

**验收**：生成期间按 Enter，1 秒内出现可见反馈；任何时候都不会出现"按了没反应"。

## P0-2 文件拖不进窗口

影响：高频 · 无替代 · 竞品默认都有

**现在**：全仓没有 `AllowDrop` / `DragDrop`（grep 为空）。而 `ComposerViewModel.ReferenceByNameAsync` 的注释写着"将来从文件树拖进对话也走这里"——链路是现成的，只差一个入口。

从资源管理器拖一个 PDF 到输入框，Windows 直接给禁止光标，窗口毫无反应。

**目标**：拖进来就等于 @ 引用，和现有发送链路完全一致。

**怎么改**：`ComposerView` 上设 `AllowDrop`；`DragOver` 时给输入框套一层虚线高亮 + "松开即引用"；`Drop` 里对每个 path 调 `AddReference(MentionItemViewModel.FromFile(path))`。多文件逐个加、去重逻辑已有（`AddReference` 里按 Id 判重）。拖文件夹先明确拒绝并提示"文件夹请用工作区选择"。

**验收**：从资源管理器拖 1 个和 3 个文件进来，都变成引用 chip；发送后模型能读到正文；拖文件夹有明确提示。

## P0-3 找不回上次说过的话

影响：越用越痛 · 无替代

**现在**：侧栏搜索只匹配标题和空间名（`MainWindowViewModel.MatchesQuery:1005-1014`），没有会话内查找，全仓无 `Key.F` 处理。标题是第一句话自动截的（`SessionText.BuildTitle`），跟内容经常没关系。

三天前让它改过一段 PowerShell，只记得"注册表代理"这个词。搜"代理"——零结果，因为那条任务叫"修复 502"。

**目标**：按内容找得到，且能看到命中的那一句。

**怎么改**：

1. `MatchesQuery` 扩到 `Entries` 正文；命中后在侧栏那行下面补一行命中摘要（截前后各 12 字，关键词反色）。会话 JSON 已全量在 `_sessionCache`，纯内存扫描，先只搜最近 200 条并给"搜索更早的任务"入口即可。
2. 对话页加 `Ctrl+F`：查找条贴在消息区右上角，显示"第 2 处 / 共 7 处"，Enter 下一处、Shift+Enter 上一处，命中滚动定位并临时高亮 1.5 秒。

**验收**：用正文里的任意词能找到那条会话并看见命中的句子；会话内三次按键内跳到第 2 处命中。

## P0-4 跑完不通知，关窗静默中断

影响：中高频 · 不可逆 · 无替代

**现在**：没有 `Closing` / `ShutdownRequested` 处理（grep 为空），没有托盘，没有系统通知，窗口标题固定 `Avalonia Assistant`（`MainWindow.axaml:6`）。后台跑的会话只有侧栏一个 11px 的转圈。

切去写文档，二十分钟后回来——不知道它什么时候跑完的，也不知道中途是不是报错了；或者关窗时它正在跑，直接没了，连"要不要等"都没问。

**目标**：交代出去的事，结果要能追回来。

**怎么改**：

1. 标题随状态变：`Avalonia Assistant — 正在执行（1）`，跑完恢复。
2. 后台任务完成或进入"等待审批"时，发一条系统通知（`Microsoft.Toolkit.Uwp.Notifications` 或直接托盘气泡），点通知回到那条会话。
3. 关窗时若存在 `IsBusy` 的会话：三选一——等它跑完 / 停止并退出 / 留在托盘继续。

**验收**：窗口不在前台时任务结束，2 秒内有可见提示且点击可回到该会话；关窗时不会静默丢掉正在跑的轮次。

# P1

## P1-5 MCP 页只说"配置了"，不说"连上了"

影响：高频失败点 · 完全不可观测

**现在**：`McpView` 只列 `capabilities.McpServers`（读的是 mcp.json），`McpViewModel` 里没有任何探测或握手动作。README 自己写着"只报配置，不代表已连上"，以及"表现是配置在、工具永远不出现，且没有明显报错"。

用户看到绿色提示"已写入 mcp.json，下一个会话会连接它们"，回对话一问——模型说没有这个工具。整个应用没有一个地方能回答"它到底起没起来"。

**目标**：让"未连接"和"连上了但没工具"都能被看见。

**怎么改**：每张服务端卡片加状态点：未连接 / 连接中 / 已连接（N 个工具）/ 启动失败；失败时展开 stderr 前 3 行；卡片上给"重试连接"。导入成功后立刻做一次真实握手（复用 `CapabilityScanner` 的启动路径），失败就直接标红，不要等到下一个会话。

**验收**：故意把 `command` 写错，能在 MCP 页看到失败原因，而不是只在对话里"凭空少一批工具"。

## P1-6 引用失效，发出去才知道

影响：中频 · 静默降级

**现在**：`BuildAttachmentAsync` 遇到文件不存在只写 `attachment.Error`，消息照发（`ComposerViewModel.cs:285-289`），用户看到的是模型回一句"没有这个文件"。

**目标**：发出前就知道哪个引用坏了。

**怎么改**：发送前对齐一次 `File.Exists`；失效的 chip 标红 + 悬停给原因；点发送时若有失效引用，给"移除失效引用并发送 / 仍然发送"两选一。文件被外部程序改动的情况不用管，发送时本来就会重读。

**验收**：@ 一个随后被删掉的文件，发送前就能看见红色标记，不会等模型来告诉你。

## P1-7 上下文压缩是无声的

影响：长会话必遇 · 损害信任

**现在**：压缩由 CodingAgent 内部触发，UI 没有任何事件或提示（"压缩"只出现在注释里）。触发点按 128k 本地估算（`CodingSessionFactory.cs:87` 自己承认是保守值）。

聊到第 40 轮，模型突然不记得前面定过的方案，用户的第一反应是"它变笨了"，而不是"上下文被压过"。

**目标**：用户随时能回答"它还记不记得前面"。

**怎么改**：输入框上方给一条细的上下文水位（当前用量 / 估算窗口），超过 70% 变警示色并提示"再聊几轮会压缩早期内容"；压缩实际发生时，在消息流里插一条系统提示："已压缩前 12 轮对话，保留摘要"。

**验收**：长会话里能看见水位变化；压缩发生后有明确的一行记录，不是静默发生。

## P1-8 审批卡出现时没人叫你

影响：阻塞型等待 · 越久越糟

**现在**：`ChatApprovalGate` 只在"用户不在底部"时飘 `FloatingHint`（`ChatViewModel.cs:746-768`）；停在底部就只是插一张卡并跟随滚动，焦点仍在输入框。整轮 Agent 已经阻塞，界面上没有第二处提示。

**目标**：不管滚到哪儿，等待确认这件事都不能被漏掉。

**怎么改**：存在 pending 审批时，在输入框正上方常驻一条"等待你确认：执行命令 dotnet build"（点击滚到卡片）；窗口标题加 · 前缀。审批卡本身加 `Esc` 拒绝（默认不把 Enter 绑成允许，避免用户正在打字时误放行）。

**验收**：无论滚动位置和焦点在哪，主界面上总有一处能看见"有操作等你确认"。

## P1-9 消息只能复制和重试

影响：追问是主循环 · 有绕法但很烦

**现在**：`AssistantMessageViewModel` 只有 Copy / Retry / Continue 三个动作（`MessageViewModels.cs:387-416`）。

读到第三段想追问"这里具体怎么改"，只能手动选中复制，或者重新打一遍上下文。

**目标**：把"就着这段继续问"变成一次点击。

**怎么改**：

1. 选中文字后浮出"引用这段"，把选区作为引用块塞进输入框（`PromptComposer` 已有附件通道，走同一条）。
2. 每条回复加"换个模型重跑"（复用 `RetryFromAsync`，多传一个 model）。
3. 会话级"导出 Markdown"，放在对话页右上角的状态胶囊旁边。

**验收**：追问一条 3 轮前的结论，不需要手打任何上下文；导出的 Markdown 能直接贴进文档。

## P1-10 工具调用行是死文本

影响：调试场景高频 · 每次多花十几秒

**现在**：`ToolCallViewModel.Summary` 是纯字符串，展开只有参数和结果两个只读文本块。路径、URL、命令都在里面，但都点不动。

跑了 `dotnet build` 失败，想打开那个目录看看，或者把报错复制去搜——全靠手选。

**目标**：工具卡里的目标物可直达。

**怎么改**：`Target` 按类型变成可点元素——路径走 `Ui.OpenExternal` 在资源管理器里显示，URL 走浏览器，命令给"复制"；结果区右上加"复制"。都不需要新窗口。

**验收**：工具卡里一次点击能到达它操作的那个文件或目录。

## P1-11 模型菜单没有"你在哪"

影响：多模型用户每次都要读一遍

**现在**：`OnModelClick` 直接按 `Models` 顺序铺 `MenuItem`，没有选中标记，没有按服务商分组（`ComposerView.axaml.cs:185-207`）。

**怎么改**：当前项打勾；按 provider 分节；末尾一条"在设置里改模型…"。如果要做成本可见，就在菜单项右侧标"贵/省"的档位，不要写单价。

**验收**：打开菜单 1 秒内知道当前是哪个，以及怎么回去改。

## P1-12 第七个工作区会凭空消失

影响：低频但必然发生 · 静默

**现在**：`MaxWorkspaces = 6`，`WorkspacePaths` 直接 `Take(6)`，没有任何提示（`MainWindowViewModel.cs:12`、`:844-862`）。加第 7 个时，浮层和侧栏都没有它。

**怎么改**：达到上限时把"新建/打开"置灰并说明"最多 6 个，先移除一个"；或者干脆改成可滚动不限量，把这个限制拿掉。

## P1-13 语音失败只丢原始异常

影响：低频 · 失败时落差大

**现在**：`VoiceError = ex.Message` 直接红字显示（`ComposerViewModel.cs:657-661`）；录音中只有时长，没有电平；没有时长上限。

DeepSeek 端点不支持转写，用户点完麦克风看到的是一串英文异常。

**怎么改**：错误分类成"端点不支持转写 / 麦克风被占用 / 没检测到语音"，各给一句下一步；录音时给 4 段电平条；超过 2 分钟自动停止并转写。

**验收**：在不支持转写的端点下点麦克风，看到的是"这个端点不支持 /audio/transcriptions，换一个支持的服务商"，不是堆栈信息。

# 已经做对，改别的地方时别弄坏

这几处是有意识设计过的，后续改动容易顺手改回去，单独列出来当护栏：

- **输入法回车保护**：`IsComposing()` 读 `PreeditText`，组词时回车不发送（`ComposerView.axaml.cs:91`、`:146-157`）。任何"改发送快捷键"的需求都要保留这一条。
- **滚动跟随的主动交还**：用户一碰滚动条或滚轮就 `_followOutput = false`，流式输出不再抢滚动（`ChatView.axaml.cs:157-231`）。加"自动滚到新消息"的功能时不要动它。
- **第一句话就落盘**：`RegisterSessionAsync` 在发出时就写文件，不等整轮跑完（`ChatViewModel.cs:325-334`）。改成"跑完再存"会丢掉中途关掉的任务。
- **草稿跨页保留**：`Dispose` 时按会话 id 存草稿，新任务有单独的待用草稿位（`ChatViewModel.cs:67-85`）。加页面跳转时别绕过这个。
- **权限变更进消息流**：切档位会插一条说明，且"已放行 N"挂在权限 pill 上（`ChatViewModel.cs:108-124`、`ComposerViewModel.cs:133-142`）。这解决了"我什么时候关掉确认的"这个真问题。
- **错误分类 + 定向按钮**：401 给"去设置"、上下文超长给"新建任务"，而不是一律"重试"（`ChatViewModel.cs:686-724`）。新增错误类型时按这个模式补，别退回到原文直出。

# 不建议做的

- **不要给每个动作加全局 toast**。权限提示已经进消息流，再来一层浮层会互相打断；只在"必须知道但不在视线内"的场景用（P0-4、P1-8）。
- **不要给消息加点赞/点踩**。这个阶段没有反馈回路去消费它，加了就是装饰。
- **不要在首页再加推荐卡片**。现在 5 个快词 + 4 张卡已经在和输入框抢注意力，再增加只会让"今天想做什么"这句话更轻。
- **不要为了统一而重做输入框**。现在这个输入框的细节密度（引用 chip、图片缩略图、活动状态、setup 提示、完全访问常驻提醒）已经是经过取舍的，重做风险远大于收益。
